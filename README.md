# Mobile Store Showcase

وب‌سایت معرفی و کاتالوگ فروشگاه فیزیکی موبایل و لوازم جانبی.

## فناوری‌ها
- PHP 8.1+، MySQL 8+ یا MariaDB، HTML5، CSS3 و Vanilla JavaScript.
- CSS واکنش‌گرا با فایل‌های مستقل Mobile / Tablet / Desktop.

## محدوده محصول
این پروژه ویترین و کاتالوگ فروشگاه فیزیکی است؛ سبد خرید، پرداخت، ثبت سفارش، حساب مشتری و انبارداری آنلاین در محدوده فعلی نیست.

## راه‌اندازی دیتابیس
1. افزونه‌های PHP یعنی `pdo_mysql` و `mbstring` را فعال کنید.
2. `.env.example` را به `.env` کپی کنید و اطلاعات اتصال دیتابیس را تنظیم کنید.
3. برای محیط محلی، `APP_ENV=development` قرار دهید؛ Debug به‌صورت پیش‌فرض خاموش است و فقط با `APP_DEBUG=true` در محیط development/local/test فعال می‌شود.
4. از ریشه پروژه اجرا کنید: `php database/migrate.php`. این فرمان هم schema پایه و هم migrationهای افزایشی پوشه `database/migrations/` را اجرا می‌کند.
5. برای ساخت مدیر از CLI، متغیرهای `ADMIN_NAME`، `ADMIN_EMAIL` و `ADMIN_PASSWORD` را تنظیم و `php database/create_admin.php` را اجرا کنید. رمز حداقل ۱۲ کاراکتر باشد.
6. در Production حتماً HTTPS فعال و حساب دیتابیس دارای حداقل مجوزهای لازم باشد؛ از حساب root استفاده نکنید.

## فاز ۴ — مدیریت کاتالوگ
- `/admin/products.php`: ایجاد، فهرست، ویرایش و حذف محصولات.
- `/admin/categories.php`: ایجاد، فهرست، ویرایش و حذف دسته‌بندی‌ها.
- اعتبارسنجی سمت سرور برای فیلدهای ضروری، طول متن، Slug یکتا، ترتیب نمایش، دسته‌بندی مرتبط و مسیر تصویر.
- تمام عملیات تغییردهنده داده با POST و CSRF محافظت می‌شوند و تمام صفحات مدیریت به AdminGuard وابسته‌اند.
- حذف دسته‌بندی محصولات را حذف نمی‌کند؛ قید دیتابیس، مقدار category_id را NULL می‌کند.
- آپلود واقعی فایل در این فاز نیست؛ فقط مسیر تصویر داخل `/assets/uploads/` پذیرفته می‌شود.

## معماری
- `app/Repositories`: تمام Queryهای SQL.
- `app/Services`: اعتبارسنجی و منطق CRUD.
- `app/Middleware`: احراز دسترسی و CSRF.
- Viewها فقط داده را نمایش می‌دهند و از Prepared Statements در Repository استفاده می‌شود.

## اجرای محلی
`php -S localhost:8000` و سپس `http://localhost:8000` را باز کنید. برای Apache، `mod_rewrite` باید فعال باشد.

## فاز ۵ — مدیریت ویترین و تنظیمات فروشگاه
- `/admin/banners.php`: ایجاد، ویرایش، حذف، فعال/غیرفعال‌سازی و مرتب‌سازی بنرها.
- `/admin/settings.php`: مدیریت نام فروشگاه، تلفن، واتساپ، ایمیل، آدرس، ساعات کاری، لینک شبکه‌های اجتماعی و نقشه.
- داده‌ها در جدول‌های موجود `banners` و `store_settings` ذخیره می‌شوند.
- اعتبارسنجی ورودی‌ها، محدودیت طول، کنترل URLهای HTTP/HTTPS، CSRF و AdminGuard اعمال شده‌اند.
- مسیر تصویر باید در `/assets/uploads/` باشد؛ آپلود واقعی فایل در این فاز پیاده‌سازی نشده است.

## فاز ۶ — اتصال ویترین عمومی به بک‌اند
- صفحه اصلی، کاتالوگ، بنر اصلی، دسته‌بندی‌ها، محصولات منتخب و اطلاعات تماس از لایه سرویس عمومی خوانده می‌شوند.
- در صورت تنظیم دیتابیس، داده‌های فعال از Repositoryها خوانده می‌شوند.
- در حالت بدون دیتابیس، نمونه‌های نمایشی برای مشاهده طراحی حفظ شده‌اند؛ این داده‌ها واقعی نیستند.
- مقادیر خروجی HTML با `htmlspecialchars` escape می‌شوند و لینک‌های خارجی با `rel="noopener noreferrer"` باز می‌شوند.
- سبد خرید، پرداخت و ثبت سفارش آنلاین عمداً اضافه نشده‌اند.

## سخت‌سازی امنیتی
- Debug در Production حتی با `APP_DEBUG=true` غیرفعال می‌ماند؛ خروجی خطاهای PHP به مرورگر ارسال نمی‌شود.
- ورود مدیر به محدودیت تلاش وابسته به IP و ترکیب IP/ایمیل مجهز است؛ سقف‌ها به‌ترتیب ۱۰ و ۵ تلاش در بازه ۱۵ دقیقه هستند.
- نشست مدیر در هر درخواست با وضعیت فعال حساب در دیتابیس تطبیق داده می‌شود و پس از ۳۰ دقیقه عدم فعالیت یا ۸ ساعت عمر مطلق منقضی می‌شود.
- مقصد بازگشت پس از ورود فقط مسیر داخلی زیر `/admin/` را می‌پذیرد.
- فرم‌های ایجاد/ویرایش/حذف بنر علاوه بر CSRF از توکن یک‌بارمصرف فرم استفاده می‌کنند تا ارسال مجدد همان فرم اثر تکراری نداشته باشد.
- جدول محدودسازی ورود با migration افزایشی `002_login_attempts` ساخته می‌شود. migrationهای اعمال‌شده checksum دارند و نباید درجا ویرایش شوند؛ تغییرات بعدی باید migration جدید باشند.
- از `.env`، رمزها و داده‌های واقعی در Git commit نکنید.

## کیفیت کد و CI
GitHub Actions در هر Push و Pull Request فایل‌های PHP را با PHP 8.2 lint می‌کند. این کنترل جایگزین تست یکپارچه MySQL یا تست مرورگر نیست.

## وضعیت اعتبارسنجی
تغییرات امنیتی در این شاخه ثبت شده‌اند، اما اجرای PHP/MySQL و تست مرورگر فقط در محیط اجرایی متصل به دیتابیس ممکن است. پس از دریافت تغییرات، `php database/migrate.php` را اجرا و سناریوهای ورود، قفل موقت، غیرفعال‌سازی مدیر، انقضای نشست و CRUD را روی محیط تست بررسی کنید.
