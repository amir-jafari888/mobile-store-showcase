# Mobile Store Showcase

وب‌سایت معرفی و کاتالوگ فروشگاه فیزیکی موبایل و لوازم جانبی.

## فناوری‌ها
- PHP 8.1+، MySQL 8+ یا MariaDB، HTML5، CSS3 و Vanilla JavaScript.
- CSS واکنش‌گرا با فایل‌های مستقل Mobile / Tablet / Desktop.

## محدوده محصول
این پروژه ویترین و کاتالوگ فروشگاه فیزیکی است؛ سبد خرید، پرداخت، ثبت سفارش، حساب مشتری و انبارداری آنلاین در محدوده فعلی نیست.

## راه‌اندازی دیتابیس
1. افزونه‌های PHP یعنی `pdo_mysql` و `mbstring` را فعال کنید.
2. دیتابیس را از phpMyAdmin بسازید و دو کاربر جدا تعریف کنید: کاربر برنامه با مجوزهای SELECT/INSERT/UPDATE/DELETE و کاربر migration با مجوزهای DDL روی همان دیتابیس.
3. `.env.example` را به `.env` کپی کنید؛ `DB_USER/DB_PASSWORD` برای برنامه و `DB_MIGRATION_USER/DB_MIGRATION_PASSWORD` برای اجرای migration هستند. اگر متغیرهای migration تنظیم نشوند، اسکریپت از حساب برنامه استفاده می‌کند.
4. برای محیط محلی، `APP_ENV=development` قرار دهید؛ Debug به‌صورت پیش‌فرض خاموش است و فقط با `APP_DEBUG=true` در محیط development/local/test فعال می‌شود.
5. از ریشه پروژه اجرا کنید: `php database/migrate.php`. این فرمان هم schema پایه و هم migrationهای افزایشی پوشه `database/migrations/` را اجرا می‌کند.
6. برای ساخت مدیر از CLI، متغیرهای `ADMIN_NAME`، `ADMIN_EMAIL` و `ADMIN_PASSWORD` را تنظیم و `php database/create_admin.php` را اجرا کنید. رمز حداقل ۱۲ کاراکتر باشد.
7. در Production حتماً HTTPS فعال و حساب دیتابیس دارای حداقل مجوزهای لازم باشد؛ از حساب root استفاده نکنید.

## فاز ۴ — مدیریت کاتالوگ
- `/admin/products.php`: ایجاد، فهرست، ویرایش و حذف محصولات.
- `/admin/categories.php`: ایجاد، فهرست، ویرایش و حذف دسته‌بندی‌ها.
- اعتبارسنجی سمت سرور برای فیلدهای ضروری، طول متن، Slug یکتا، ترتیب نمایش، دسته‌بندی مرتبط و مسیر تصویر.
- تمام عملیات تغییردهنده داده با POST و CSRF محافظت می‌شوند و تمام صفحات مدیریت به AdminGuard وابسته‌اند.
- حذف دسته‌بندی محصولات را حذف نمی‌کند؛ قید دیتابیس، مقدار category_id را NULL می‌کند.
- آپلود واقعی فایل در این فاز نیست؛ فقط مسیر تصویر داخل `/assets/uploads/` پذیرفته می‌شود.

## معماری
- `app/Repositories`: تمام Queryهای SQL.
- `app/Services`: اعتبارسنجی و منطق CRUD.
- `app/Middleware`: احراز دسترسی و CSRF.
- Viewها فقط داده را نمایش می‌دهند و از Prepared Statements در Repository استفاده می‌شود.

## اجرای محلی
`php -S localhost:8000` و سپس `http://localhost:8000` را باز کنید. برای Apache، `mod_rewrite` باید فعال باشد.

## فاز ۵ — مدیریت ویترین و تنظیمات فروشگاه
- `/admin/banners.php`: ایجاد، ویرایش، حذف، فعال/غیرفعال‌سازی و مرتب‌سازی بنرها.
- `/admin/settings.php`: مدیریت نام فروشگاه، تلفن، واتساپ، ایمیل، آدرس، ساعات کاری، لینک شبکه‌های اجتماعی و نقشه.
- داده‌ها در جدول‌های موجود `banners` و `store_settings` ذخیره می‌شوند.
- اعتبارسنجی ورودی‌ها، محدودیت طول، کنترل URLهای HTTP/HTTPS، CSRF و AdminGuard اعمال شده‌اند.
- مسیر تصویر باید در `/assets/uploads/` باشد؛ آپلود واقعی فایل در این فاز پیاده‌سازی نشده است.

## فاز ۶ — اتصال ویترین عمومی به بک‌اند
- صفحه اصلی، کاتالوگ، بنر اصلی، دسته‌بندی‌ها، محصولات منتخب و اطلاعات تماس از لایه سرویس عمومی خوانده می‌شوند.
- در صورت تنظیم دیتابیس، داده‌های فعال از Repositoryها خوانده می‌شوند.
- در حالت بدون دیتابیس، نمونه‌های نمایشی برای مشاهده طراحی حفظ شده‌اند؛ این داده‌ها واقعی نیستند.
- مقادیر خروجی HTML با `htmlspecialchars` escape می‌شوند و لینک‌های خارجی با `rel="noopener noreferrer"` باز می‌شوند.
- سبد خرید، پرداخت و ثبت سفارش آنلاین عمداً اضافه نشده‌اند.

## سخت‌سازی امنیتی
- Debug در Production حتی با `APP_DEBUG=true` غیرفعال می‌ماند؛ خروجی خطاهای PHP به مرورگر ارسال نمی‌شود.
- ورود مدیر به محدودیت تلاش وابسته به IP و ترکیب IP/ایمیل مجهز است؛ سقف‌ها به‌ترتیب ۱۰ و ۵ تلاش در بازه ۱۵ دقیقه هستند.
- نشست مدیر در هر درخواست با وضعیت فعال حساب در دیتابیس تطبیق داده می‌شود و پس از ۳۰ دقیقه عدم فعالیت یا ۸ ساعت عمر مطلق منقضی می‌شود.
- مقصد بازگشت پس از ورود فقط مسیر داخلی زیر `/admin/` را می‌پذیرد.
- فرم‌های ایجاد/ویرایش/حذف محصولات، دسته‌بندی‌ها و بنرها علاوه بر CSRF از توکن یک‌بارمصرف فرم استفاده می‌کنند تا ارسال مجدد همان فرم اثر تکراری نداشته باشد.
- جدول محدودسازی ورود با migration افزایشی `002_login_attempts` ساخته می‌شود. migrationهای اعمال‌شده checksum دارند و نباید درجا ویرایش شوند؛ تغییرات بعدی باید migration جدید باشند.
- از `.env`، رمزها و داده‌های واقعی در Git commit نکنید.

## کیفیت کد و CI
GitHub Actions در هر Push و Pull Request فایل‌های PHP را با PHP 8.2 lint می‌کند، Migrationها را دو بار برای بررسی تکرارپذیری اجرا می‌کند و تست‌های یکپارچه MySQL برای ورود، قفل تلاش‌ها، ابطال نشست، CSRF و CRUD را اجرا می‌کند. تست مرورگر و آزمون نفوذ عملی همچنان جداگانه لازم‌اند.

## وضعیت اعتبارسنجی
تست‌های PHP lint و MySQL integration در CI اجرا می‌شوند. اجرای واقعی روی هاست مقصد، تست مرورگر، بررسی تنظیمات Apache/PHP و آزمون نفوذ عملی هنوز باید روی محیط استقرار انجام شوند. پس از دریافت تغییرات، `.env` را با حساب‌های دیتابیس تنظیم و `php database/migrate.php` را اجرا کنید.


## راه‌اندازی محلی با XAMPP و phpMyAdmin

در XAMPP ممکن است اتصال PDO با `DB_HOST=127.0.0.1` از سمت MySQL با میزبان `localhost` شناسایی شود. حساب‌های MySQL با Host متفاوت، حساب‌های جداگانه‌ای هستند؛ بنابراین داشتن مجوز برای `'mobile_store_app'@'127.0.0.1'` لزوماً مجوز `'mobile_store_app'@'localhost'` را فراهم نمی‌کند.

برای تنظیم حساب‌های محلی:

1. مطمئن شوید دیتابیس `mobile_store` از قبل در phpMyAdmin وجود دارد.
2. فایل `database/xampp-local-users.sql` را در phpMyAdmin باز و اجرا کنید. این فایل فقط حساب‌ها و مجوزهای MySQL با Host برابر `localhost` را تنظیم می‌کند و هیچ جدول یا داده‌ای را تغییر نمی‌دهد.
3. قبل از اجرا، هر دو مقدار `CHANGE_THIS_APP_PASSWORD` و `CHANGE_THIS_MIGRATION_PASSWORD` را با رمزهای انتخابی خود جایگزین کنید.
4. همان رمزها را در فایل محلی و Git-ignored پروژه یعنی `.env` قرار دهید:

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=mobile_store
DB_USER=mobile_store_app
DB_PASSWORD=رمز_انتخابی_برنامه
DB_MIGRATION_USER=mobile_store_migrator
DB_MIGRATION_PASSWORD=رمز_انتخابی_مهاجرت
DB_CHARSET=utf8mb4
```

5. Apache و MySQL را در XAMPP اجرا و صفحه سایت را دوباره باز کنید.

این تنظیم مخصوص محیط توسعه محلی است. فایل SQL حساب `root` ایجاد نمی‌کند، از حساب `root` برای اتصال برنامه استفاده نمی‌کند و به دیتابیس یا جدول‌های موجود دست نمی‌زند. فایل `.env` را هرگز commit نکنید.
